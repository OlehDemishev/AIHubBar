# ClaudePult: режимы работы, шаблоны и помощник — техзадание

Основное ТЗ — `docs/SPEC.md` (пульт программиста, этапы 1–8 сделаны). Этот документ превращает ClaudePult из инструмента одного сценария в пульт для разных видов работы с Claude. Код, комментарии, коммиты, STATUS — на английском, интерфейс — на русском.

Согласовано с Олегом 2026-10-30: режимы собираются из кубиков; готовые режимы — «Шаблоны»; «Помощник» собирает режим кубик за кубиком; календарь публикаций — сразу; строка меню настраивается полностью.

---

## 1. Понятия

- **Кубик** — одна настраиваемая часть поведения: откуда брать проекты, что в карточке, какие команды Claude, какие права в фоне и т. д. (§3).
- **Режим** — набор кубиков с названием и значком: «Разработчик (GitHub)», «Видео» и т. п. Режим хранится как JSON в `~/Library/Application Support/ClaudePult/modes/<id>.json`, его можно экспортировать в файл и импортировать.
- **Шаблон** — встроенный режим, с которого начинают (§4). Шаблоны — данные, а не код: лежат в бандле как JSON.
- **Помощник** — пошаговая сборка режима (§5).

**Общее для всех режимов** (не переключается): лимиты подписки, прогноз, виджет; сессии Claude Code; очередь «после сброса»; уведомления и Telegram; строка меню (§7, с возможными добавками от режима).

## 2. Панель и переключение режимов

- Включённых режимов может быть несколько. Если их больше одного, вверху панели — переключатель (значок + название каждого режима). Последний выбранный запоминается.
- Лимиты и сессии — общие блоки; проекты, карточки, команды Claude, общие команды и календарь — от текущего режима.
- В Настройках вкладка **«Режимы»**: слева список (включить/выключить, порядок, «Добавить режим» → помощник, «Дублировать», «Экспорт», «Импорт», «Удалить»), справа кубики выбранного режима для тонкой настройки и «Сбросить к шаблону».

## 3. Кубики

| Кубик | Варианты и настройки |
|---|---|
| **Источник проектов** | git-репозитории через `report.py` · папки (каждая подпапка — проект) · одна папка-«входящие» · без проектов. Путь к папке. |
| **Карточка проекта** | STATUS.md (шапка Stage/Now/Next/Needs) · `проект.md` (этап, дедлайн, дата публикации, формат, главный файл, площадка) · без карточки |
| **Этапы** | упорядоченный список с цветами; переход этапа прямо из панели |
| **Метрики в строке проекта** | ветка · незакоммиченное · PR и CI · последняя активность · слова · хронометраж (слов/мин настраивается) · время чтения · страницы · число источников · дедлайн · дата публикации |
| **Команды Claude** | набор шаблонов задач: название, промт с подстановками (`{файл}`, `{проект}`, `{формат}`, `{хронометраж}`, `{площадка}`, `{текст}`), на чём запускать (проект / выбранный файл), куда результат (новый файл рядом с шаблоном имени, никогда не перезаписывать) |
| **Где запускать** | Терминал · Фон · спрашивать (+ «Запомнить выбор») |
| **Права в фоне** | «код» (как сейчас, SPEC §2.4) · «только файлы» (чтение/правка внутри папки проекта, без Bash, без сети) · «файлы + поиск в интернете» |
| **Календарь** | выкл · дедлайны и даты публикации проектов · + контент-план (§6) |
| **Блоки панели** | какие показывать и в каком порядке: проекты, календарь, общие команды |
| **Общие команды** | `_daily-report` (отчёт, сводка, последний отчёт, очистка) · свои команды-шаблоны без проекта · нет |
| **Добавки к строке меню** | элементы режима для строки меню (§7): ближайший дедлайн, проекты в работе и т. п. |

Кубики, которые работают только с git-репозиториями (STATUS.md, PR/CI, ветки, «Следующий шаг» с PR, очистка сборок, `_daily-report`), помощник показывает, только если источник — git-репозитории.

## 4. Шаблоны

1. **Разработчик (GitHub)** — текущее поведение ClaudePult без изменений: репозитории из `report.py`, STATUS.md, «Следующий шаг» / «Своя задача» / «Завершить», Терминал и фон с правами «код», worktree при занятой папке, `_daily-report`-команды.
2. **Видео (YouTube, Shorts, Reels)** — папка на ролик; этапы: идея → ресёрч → сценарий → запись → монтаж → опубликовано; метрики: слова, хронометраж, дедлайн, дата публикации; команды: хуки, версия для Shorts (60 с), описание и таймкоды, заголовки и идеи обложек, проверка фактов, перевод, своя задача; календарь: дедлайны и публикации.
3. **Тексты (статьи, блог, рассылка, Telegram-канал)** — этапы: идея → черновик → редактура → опубликовано; метрики: слова, время чтения, дата публикации; команды: редактура и корректура, другой тон, сократить/расширить, SEO-заголовок и описание, нарезка в посты для площадок, своя задача; календарь.
4. **Ресёрч и учёба** — папка на тему с источниками (PDF, ссылки, заметки); метрики: источники, объём заметок, дедлайн; команды: конспект источника, цитаты со ссылками, сводная таблица, «что ещё не изучено», план; права: «файлы + поиск в интернете».
5. **Соцсети и маркетинг** — проект = кампания или площадка; календарь с контент-планом (§6) — главный блок; команды: посты под площадки из одного исходника, варианты рекламы, A/B-заголовки, ответы на типовые комментарии, «заполнить контент-план на неделю».
6. **Свой** — пустой набор кубиков (перевод, офис, учёба, что угодно).

Тексты промтов шаблонов согласовать с Олегом до этапа 3 (в JSON, правятся без пересборки).

## 5. Помощник

Пошаговая сборка, по одному кубику на экран, справа — живой предпросмотр панели и строки меню на примерных данных. Назад/вперёд, «Пропустить» (оставить как в шаблоне).

1. Чем вы занимаетесь? — выбор шаблона или «С нуля».
2. Где лежат проекты? — выбор папки; помощник смотрит, что внутри (git-репозитории / папки) и предлагает источник.
3. Этапы — редактируемый список.
4. Что показывать в строке проекта — метрики.
5. Календарь — выкл / даты / контент-план; напоминания.
6. Команды Claude — отметить, поправить промты, добавить свои.
7. Где запускать и что разрешить в фоне.
8. Блоки панели и их порядок.
9. Строка меню (§7) — пресет или свои элементы.
10. Название и значок → «Готово».

Помощник открывается при первом запуске (если режимов нет) и кнопкой «Добавить режим». Дальше всё правится на вкладке «Режимы» без пошагового прохода.

## 6. Календарь (сразу, в первой волне)

- **Что в нём:** дедлайны и даты публикации проектов (из `проект.md`: `Дедлайн:`, `Публикация: 2026-11-05 18:00`), записи контент-плана (режим «Соцсети»).
- **Контент-план:** файл `контент-план.md` в папке режима или кампании — таблица Markdown, которую можно править руками и которую понимает Claude:

```markdown
| Дата | Время | Площадка | Тема | Статус | Файл |
|---|---|---|---|---|---|
| 2026-11-03 | 18:00 | Instagram | Закулисье съёмки | черновик | посты/закулисье.md |
```

- **В панели:** блок «Ближайшее» — 7 дней вперёд, просроченное красным; клик — открыть проект/файл.
- **Окно «Календарь»:** месяц и неделя, все включённые режимы или только текущий, цвет по режиму/площадке; перетаскивание меняет дату (пишется обратно в `проект.md` / `контент-план.md`); новая запись — двойным кликом.
- **Напоминания:** уведомление за N часов/дней до даты (настраивается), по желанию — в Telegram; клик открывает проект.
- **Связь с Claude:** команда «Заполнить контент-план на неделю» и «Подготовить посты по плану» — результат в файлы, даты — в контент-план.
- **Системный «Календарь» macOS:** экспорт в `.ics`-файл (подписка) — этапом позже; запись через EventKit требует разрешения — по желанию.

## 7. Строка меню — полная настройка

Строка меню собирается из **элементов**, каждый включается, настраивается и переставляется. Живой предпросмотр в Настройках (вкладка «Строка меню») и в помощнике.

| Элемент | Настройки |
|---|---|
| Значок | ✦ / другой символ / значок текущего режима / скрыть (если есть другие элементы) |
| Состояние проектов | красная точка при проблемах · выкл |
| Сессия (5 ч) | число % · кольцо · полоска; цвет по уровню / одноцветно; показывать всегда / только выше N % |
| Неделя | то же |
| Неделя по модели | то же, выбор модели |
| До сброса сессии | «2:14» / «2 ч 14 мин» |
| Прогноз | «до 16:40» — только когда не хватит до сброса |
| Ждут ответа | ✋N · только если > 0 |
| Работают сессии | N · только если > 0 |
| Фоновые задачи | ⏳N · только если > 0 |
| Отложенные запуски | N |
| Ближайший дедлайн/публикация | «Ролик · 2 дн» · только если ближе N дней |
| Свободное место | только если меньше порога |
| Текущий режим | значок / короткое название |

Общие настройки: порядок (перетаскиванием), разделитель (пробел / « · » / «|»), размер текста (обычный / мелкий), цвет (по уровню / одноцветно), компактность. Пресеты: **«Минимум»** (значок, точки и ✋ при событиях), **«Лимиты»** (как сейчас), **«Всё»**, **«Свой»**. Набор строки меню — общий; режим может добавить свои элементы (§3, «Добавки»).

Ограничения macOS: строка меню — одна картинка (как сейчас, `MenuBarRenderer`); при большом числе элементов показывается предупреждение о ширине.

## 8. Чего не делать

- Не ломать режим «Разработчик (GitHub)»: для Олега всё работает как сейчас.
- Не читать и не отправлять тексты никуда, кроме Claude Code, запущенного у пользователя; не трогать файлы вне папки проекта; не перезаписывать файлы пользователя.
- Не держать данные пользователя в собственном формате, который нельзя прочитать без ClaudePult: карточки и контент-план — Markdown.

## 9. Этапы (каждый — ветка, проверки, установка, проверка вживую, STATUS, PR)

1. **Модель режимов.** JSON-хранилище, перенос текущих настроек в режим «Разработчик (GitHub)», переключатель в панели, вкладка «Режимы» (просмотр кубиков, включение/порядок). Для Олега поведение не меняется.
2. **Строка меню как конструктор** (§7): элементы, пресеты, предпросмотр, вкладка «Строка меню».
3. **Кубики для не-программистов:** проекты-папки, `проект.md`, этапы, метрики; движок шаблонов задач; фон с правами «только файлы» (проверка прав вживую).
4. **Календарь** (§6): даты проектов, контент-план, блок «Ближайшее», окно «Календарь», напоминания.
5. **Шаблоны** «Видео», «Тексты», «Ресёрч», «Соцсети», «Свой» (промты согласовать с Олегом).
6. **Помощник** (§5) с предпросмотром, первый запуск, экспорт/импорт режимов.
7. **Позже:** права «файлы + поиск в интернете», экспорт календаря в `.ics`, быстрый запрос по выделенному тексту, пакетные задачи, `.docx`.

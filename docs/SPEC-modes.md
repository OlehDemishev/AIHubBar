# ClaudePult: режимы работы, шаблоны, помощник и сервисы AI — техзадание

Основное ТЗ — `docs/SPEC.md` (пульт программиста, этапы 1–8 сделаны). Этот документ превращает ClaudePult из личного инструмента одного сценария в пульт для разных видов работы с AI — для всех. Код, комментарии, коммиты, STATUS — на английском, интерфейс — на русском (английский — см. §10). Тексты встроенных шаблонов — `docs/TEMPLATES.md`.

Согласовано с Олегом 2026-10-30:
- режимы собираются из кубиков; готовые режимы — «Шаблоны»; «Помощник» собирает режим кубик за кубиком; календарь публикаций — сразу; строка меню настраивается полностью;
- **ClaudePult — для всех**, не только для Олега; его нынешняя настройка — это просто его сохранённый режим (§12);
- **кроме Claude — другие крупные сервисы AI** (§11): человек сравнит и сам увидит, где лучше;
- **настройки сохраняются в файл**, чтобы делиться ими и переносить на другие Маки (§12).

## 1. Понятия

- **Кубик** — одна настраиваемая часть поведения: откуда брать проекты, что в карточке, какие команды Claude, какие права в фоне и т. д. (§3).
- **Режим** — набор кубиков с названием и значком: «Разработчик (GitHub)», «Видео» и т. п. Режим хранится как JSON в `~/Library/Application Support/ClaudePult/modes/<id>.json`, его можно экспортировать в файл и импортировать.
- **Шаблон** — встроенный режим, с которого начинают (§4). Шаблоны — данные, а не код: лежат в бандле как JSON; тексты команд — `docs/TEMPLATES.md`.
- **Помощник** — пошаговая сборка режима (§5).

- **Сервис AI** — кто выполняет команды: агент (Claude Code, Codex CLI, Gemini CLI…) или модель по API (§11).

**Общее для всех режимов** (не переключается): лимиты и расход сервисов AI, прогноз, виджет; сессии агентов; очередь «после сброса»; уведомления и Telegram; строка меню (§7, с возможными добавками от режима).

## 2. Панель и переключение режимов

- Включённых режимов может быть несколько. Если их больше одного, вверху панели — переключатель (значок + название каждого режима). Последний выбранный запоминается.
- Лимиты и сессии — общие блоки; проекты, карточки, команды Claude, общие команды и календарь — от текущего режима.
- В Настройках вкладка **«Режимы»**: слева список (включить/выключить, порядок, «Добавить режим» → помощник, «Дублировать», «Экспорт», «Импорт», «Удалить»), справа кубики выбранного режима для тонкой настройки и «Сбросить к шаблону».

## 3. Кубики

| Кубик | Варианты и настройки |
|---|---|
| **Источник проектов** | git-репозитории (встроенный сканер: ветка, незакоммиченное, PR и CI через `gh`, если есть) · git-репозитории через `report.py` (как у Олега) · папки (каждая подпапка — проект) · одна папка-«входящие» · без проектов. Путь к папке. |
| **Карточка проекта** | STATUS.md (шапка Stage/Now/Next/Needs) · `проект.md` (этап, дедлайн, дата публикации, формат, главный файл, площадка) · без карточки |
| **Этапы** | упорядоченный список с цветами; переход этапа прямо из панели |
| **Метрики в строке проекта** | ветка · незакоммиченное · PR и CI · последняя активность · слова · хронометраж (слов/мин настраивается) · время чтения · страницы · число источников · дедлайн · дата публикации |
| **Команды** | набор шаблонов задач (тексты — `docs/TEMPLATES.md`): название, задача с подстановками (`{файл}`, `{проект}`, `{формат}`, `{хронометраж}`, `{площадка}`, `{текст}`), на чём запускать (проект / выбранный файл), куда результат (новый файл рядом по шаблону имени, никогда не перезаписывать), каким сервисом AI (по умолчанию режима или свой) |
| **Сервис AI по умолчанию** | агент или модель по API для команд режима; «Сравнить» — запустить ту же команду 2–3 сервисами (§11.4) |
| **Где запускать** | Терминал · Фон · спрашивать (+ «Запомнить выбор») |
| **Права в фоне** | «код» (как сейчас, SPEC §2.4) · «только файлы» (чтение/правка внутри папки проекта, без Bash, без сети) · «файлы + поиск в интернете» |
| **Календарь** | выкл · дедлайны и даты публикации проектов · + контент-план (§6) |
| **Блоки панели** | какие показывать и в каком порядке: проекты, календарь, общие команды |
| **Общие команды** | `_daily-report` (отчёт, сводка, последний отчёт, очистка) · свои команды-шаблоны без проекта · нет |
| **Добавки к строке меню** | элементы режима для строки меню (§7): ближайший дедлайн, проекты в работе и т. п. |

Кубики, которые работают только с git-репозиториями (STATUS.md, PR/CI, ветки, «Следующий шаг» с PR, очистка сборок, `_daily-report`), помощник показывает, только если источник — git-репозитории.

## 4. Шаблоны

1. **Разработчик (GitHub)** — общий шаблон для программиста: репозитории (встроенный сканер), STATUS.md, если есть, «Следующий шаг» / «Своя задача» / «Завершить» с промтами без привязки к чьим-то правилам («работай по правилам проекта: CLAUDE.md / AGENTS.md, если они есть»), Терминал и фон с правами «код», worktree при занятой папке. Нынешняя настройка Олега (`report.py`, `_daily-report`, его промты, `~/Projects/CLAUDE.md`) — его личный режим «Разработчик — Олег», сохранённый файлом (§12), а не встроенный шаблон.
2. **Видео (YouTube, Shorts, Reels)** — папка на ролик; этапы: идея → ресёрч → сценарий → запись → монтаж → опубликовано; метрики: слова, хронометраж, дедлайн, дата публикации; команды: хуки, версия для Shorts (60 с), описание и таймкоды, заголовки и идеи обложек, проверка фактов, перевод, своя задача; календарь: дедлайны и публикации.
3. **Тексты (статьи, блог, рассылка, Telegram-канал)** — этапы: идея → черновик → редактура → опубликовано; метрики: слова, время чтения, дата публикации; команды: редактура и корректура, другой тон, сократить/расширить, SEO-заголовок и описание, нарезка в посты для площадок, своя задача; календарь.
4. **Ресёрч и учёба** — папка на тему с источниками (PDF, ссылки, заметки); метрики: источники, объём заметок, дедлайн; команды: конспект источника, цитаты со ссылками, сводная таблица, «что ещё не изучено», план; права: «файлы + поиск в интернете».
5. **Соцсети и маркетинг** — проект = кампания или площадка; календарь с контент-планом (§6) — главный блок; команды: посты под площадки из одного исходника, варианты рекламы, A/B-заголовки, ответы на типовые комментарии, «заполнить контент-план на неделю».
6. **Свой** — пустой набор кубиков (перевод, офис, учёба, что угодно).

Тексты промтов шаблонов согласовать с Олегом до этапа 3 (в JSON, правятся без пересборки).

## 5. Помощник

Пошаговая сборка, по одному кубику на экран, справа — живой предпросмотр панели и строки меню на примерных данных. Назад/вперёд, «Пропустить» (оставить как в шаблоне).

1. Чем вы занимаетесь? — выбор шаблона или «С нуля».
2. Где лежат проекты? — выбор папки; помощник смотрит, что внутри (git-репозитории / папки) и предлагает источник.
3. Этапы — редактируемый список.
4. Что показывать в строке проекта — метрики.
5. Календарь — выкл / даты / контент-план; напоминания.
6. Сервис AI — какой агент или модель выполняет команды (показываются установленные агенты и сервисы с ключами; «Подключить…» — §11.3).
7. Команды — отметить, поправить тексты, добавить свои.
8. Где запускать и что разрешить в фоне.
9. Блоки панели и их порядок.
10. Строка меню (§7) — пресет или свои элементы.
11. Название и значок → «Готово».

При первом запуске помощник начинается с шага 0: «Перенести настройки с другого Мака или от коллеги?» → импорт файла (§12).

Помощник открывается при первом запуске (если режимов нет) и кнопкой «Добавить режим». Дальше всё правится на вкладке «Режимы» без пошагового прохода.

## 6. Календарь (сразу, в первой волне)

- **Что в нём:** дедлайны и даты публикации проектов (из `проект.md`: `Дедлайн:`, `Публикация: 2026-11-05 18:00`), записи контент-плана (режим «Соцсети»).
- **Контент-план:** файл `контент-план.md` в папке режима или кампании — таблица Markdown, которую можно править руками и которую понимает Claude:

```markdown
| Дата | Время | Площадка | Тема | Статус | Файл |
|---|---|---|---|---|---|
| 2026-11-03 | 18:00 | Instagram | Закулисье съёмки | черновик | посты/закулисье.md |
```

- **В панели:** блок «Ближайшее» — 7 дней вперёд, просроченное красным; клик — открыть проект/файл.
- **Окно «Календарь»:** месяц и неделя, все включённые режимы или только текущий, цвет по режиму/площадке; перетаскивание меняет дату (пишется обратно в `проект.md` / `контент-план.md`); новая запись — двойным кликом.
- **Напоминания:** уведомление за N часов/дней до даты (настраивается), по желанию — в Telegram; клик открывает проект.
- **Связь с Claude:** команда «Заполнить контент-план на неделю» и «Подготовить посты по плану» — результат в файлы, даты — в контент-план.
- **Системный «Календарь» macOS:** экспорт в `.ics`-файл (подписка) — этапом позже; запись через EventKit требует разрешения — по желанию.

## 7. Строка меню — полная настройка

Строка меню собирается из **элементов**, каждый включается, настраивается и переставляется. Живой предпросмотр в Настройках (вкладка «Строка меню») и в помощнике.

| Элемент | Настройки |
|---|---|
| Значок | ✦ / другой символ / значок текущего режима / скрыть (если есть другие элементы) |
| Состояние проектов | красная точка при проблемах · выкл |
| Сессия (5 ч) | число % · кольцо · полоска; цвет по уровню / одноцветно; показывать всегда / только выше N % |
| Неделя | то же |
| Неделя по модели | то же, выбор модели |
| Лимит другого сервиса | то же, для сервисов, которые отдают лимиты (§11.5) |
| Расход по API за месяц | «$4,20» / % от бюджета · только выше N % |
| До сброса сессии | «2:14» / «2 ч 14 мин» |
| Прогноз | «до 16:40» — только когда не хватит до сброса |
| Ждут ответа | ✋N · только если > 0 |
| Работают сессии | N · только если > 0 |
| Фоновые задачи | ⏳N · только если > 0 |
| Отложенные запуски | N |
| Ближайший дедлайн/публикация | «Ролик · 2 дн» · только если ближе N дней |
| Свободное место | только если меньше порога |
| Текущий режим | значок / короткое название |

Общие настройки: порядок (перетаскиванием), разделитель (пробел / « · » / «|»), размер текста (обычный / мелкий), цвет (по уровню / одноцветно), компактность. Пресеты: **«Минимум»** (значок, точки и ✋ при событиях), **«Лимиты»** (как сейчас), **«Всё»**, **«Свой»**. Набор строки меню — общий; режим может добавить свои элементы (§3, «Добавки»).

Ограничения macOS: строка меню — одна картинка (как сейчас, `MenuBarRenderer`); при большом числе элементов показывается предупреждение о ширине.

## 11. Сервисы AI

Цель: дать человеку работать в ClaudePult с тем сервисом, к которому он привык, и легко сравнить с Claude. Claude остаётся сервисом по умолчанию и самым полно поддержанным (лимиты подписки, hooks сессий, права в фоне).

### 11.1 Два вида сервисов

**Агенты** — работают с файлами в папке проекта, запускаются в Терминале или в фоне, умеют многошаговые задачи:

| Агент | Запуск | Права в фоне | Сессии | Лимиты |
|---|---|---|---|---|
| Claude Code | есть (`claude`, `claude -p`) | правила allow/deny (SPEC §2.4) | hooks (SPEC §2.3) | подписка (SPEC §2.8) |
| OpenAI Codex CLI | `codex`, `codex exec` | песочница и подтверждения Codex | по процессу и папке | проверить: rate limits в логах сессий |
| Google Gemini CLI | `gemini`, `gemini -p` | режим подтверждений / песочница | по процессу и папке | проверить |
| GitHub Copilot CLI | `copilot` | проверить | по процессу | проверить |
| Cursor CLI | `cursor-agent` | проверить | по процессу | — |
| Свой агент | шаблон команды (`opencode`, `aider` …) | только Терминал | по процессу | — |

Все флаги, режимы прав и форматы вывода чужих CLI **сверить с их документацией и `--help` перед этапом 3** — как для Claude Code, не по памяти. Агент без надёжного запрета действий в фоне запускается **только в Терминале**.

**Модели по API** — для текстовых команд без работы с файлами (хуки, заголовки, «переписать тоном», описание, перевод): ClaudePult сам передаёт текст файла и сам записывает результат рядом. Прав в фоне не нужно — модель ничего не трогает.

Первая пятёрка кроме Claude: **OpenAI** (GPT), **Google** (Gemini), **xAI** (Grok), **DeepSeek**, **Mistral**; плюс **Anthropic API** и **«совместимый с OpenAI»** (OpenRouter, локальные Ollama / LM Studio — бесплатно и без облака). Модель выбирается из списка сервиса.

### 11.2 В интерфейсе

- В карточке команды — сервис по умолчанию режима и меню «Выполнить в…».
- Блок «Лимиты» становится «Лимиты и расход»: Claude — как сейчас; агенты — что они отдают; модели по API — токены и стоимость запросов ClaudePult за день/месяц (считает сам по ответам API) и месячный бюджет с предупреждением.
- Сессии — агенты с hooks (Claude) подробно, остальные — «работает в <папка>» по процессу.

### 11.3 Подключение

- Агенты — найти установленные (`/opt/homebrew/bin`, `~/.local/bin`, npm-глобальные), показать версию; вход — их собственный (`codex login`, `gemini` и т. п.), ClaudePult токены не трогает.
- Модели по API — человек вставляет ключ в Настройках → «Сервисы AI»; ключ хранится только в связке ключей macOS, не логируется, не попадает в экспорт (§12); кнопка «Проверить» делает короткий запрос.

### 11.4 «Сравнить»

У любой команды — «Сравнить…»: выбрать 2–3 сервиса, ClaudePult запускает одну и ту же задачу и кладёт результаты рядом: `хуки (Claude).md`, `хуки (GPT).md`, `хуки (Gemini).md`, плюс окно «рядом» для чтения. Без оценок от ClaudePult — человек решает сам.

### 11.5 Чего не делать

- Не хранить ключи и токены вне связки ключей; не выводить их; не класть в экспорт.
- Не отправлять тексты сервису, который человек не выбрал для этой команды.
- Не притворяться, что у сервиса есть лимиты или права, если их нельзя надёжно получить: честное «нет данных».

## 12. Настройки в файле: поделиться и перенести

- **Экспорт** (Настройки → Основные → «Экспорт настроек…»): один файл `*.claudepult` (JSON) — режимы, строка меню, внешний вид, пороги, выбор сервисов, шаблоны команд. **Без** ключей, токенов, журналов и данных сессий. Пути внутри домашней папки пишутся как `~/…`.
- **Экспорт режима** — один режим отдельным файлом, чтобы поделиться им («мой режим для YouTube»).
- **Импорт:** предпросмотр, что изменится; «Заменить всё» или «Добавить режимы»; если папок из файла нет на этом Маке — предложить выбрать свои; недостающие сервисы (агент не установлен, нет ключа) — помечены «подключить».
- Двойной клик по файлу `*.claudepult` открывает импорт.
- Режим Олега «Разработчик — Олег» хранится так же и лежит в репозитории как пример: `docs/modes/oleh-developer.claudepult` (без личных секретов).

## 13. Языки

Решено с Олегом 2026-10-30 — после всех этапов, в таком порядке (по доле трафика AI-чатботов и рынкам):

1. **Английский** — США, Великобритания, Канада, Австралия, Филиппины, большая часть пользователей из Индии. Без него приложение для всех не имеет смысла; становится языком по умолчанию для систем не из списка.
2. **Испанский** — Мексика, Испания, Колумбия, Аргентина, испаноязычные США.
3. **Португальский (Бразилия, pt-BR)** — именно бразильский вариант.
4. **Французский** — Франция, Бельгия, Квебек, франкоязычная Африка.
5. **Немецкий** — Германия, Австрия, Швейцария.
6. **Японский** — платёжеспособная аудитория, ждёт качественной локализации (проверка носителем).
7. **Индонезийский.**
8. **Корейский.**
9. **Итальянский.**
10. **Арабский** — ОАЭ, Саудовская Аравия, Египет; нужна вёрстка справа налево (RTL): панель, строка меню, окна, календарь.
11. **Польский.**
12. **Украинский.**

Русский остаётся (исходный язык интерфейса).

Как делать:
- Все строки интерфейса — в String Catalog (`Localizable.xcstrings`); в коде — только ключи и `String(localized:)`, форматы чисел, дат и единиц — системные (как уже сделано для «ГБ»).
- Тексты встроенных шаблонов (`docs/TEMPLATES.md`) переводятся отдельно и адаптируются под язык (площадки, примеры), а не дословно; имена файлов результатов — на языке интерфейса.
- Язык интерфейса — системный, с выбором в Настройках → Основные.
- `help.txt` бота Олега не переводится (личный инструмент).
- Проверка: снимки панели и окон на каждом языке (длинные немецкие строки, японский и корейский шрифты, RTL для арабского); перевод — машинный черновик + вычитка носителем для японского, корейского и арабского как минимум.

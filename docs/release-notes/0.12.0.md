## New

- **Codex approvals** — “Allow” and “Deny” for Codex's permission requests in the notification, the session row and Telegram, like Claude's. Update the Codex hook in Settings → AI Services → Codex, then trust it once in Codex's `/hooks`.
- **Codex in the background** — Quick Request sends a task to Codex without a window (`codex exec`): it writes only in the project folder, can commit, has no network, and the result comes as a notification, like Claude's. Near Codex's own limit such a task is paused until the reset, and a new one asks first.
- **Hand over to Codex** — when Claude is near its limit, the launch question offers “To Codex”, and a paused or failed background task has “Hand Over to Codex” in its menu: Codex continues in the same folder and is told to look at the work already there.
- **Review by the other service** — a finished background task has “Review in Codex” (or “Review in Claude” for Codex's work): the other service reads the changes, changes nothing and answers “OK” or a list of problems.
- **One task, two services** — in Quick Request tick “Also in Codex — to compare”: Claude and Codex get the same task, each in its own worktree, and one notification says how both ended.
- **Skills and plugins** — the Claude Code window has a third tab: the skills of Claude Code and Codex and Claude Code's plugins with a switch each, and the hooks of both to look at.

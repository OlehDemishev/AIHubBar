# ClaudePult для Linux — техзадание

Только спецификация: реализацию не начинаем, пока Олег не скажет (2026-10-30). Что делает ClaudePult, описано в `docs/SPEC.md`, `docs/SPEC-modes.md` и `docs/SPEC-profiles.md`. Здесь — как то же самое сделать на Linux. Технология, формат данных и этапы общие с Windows (`docs/SPEC-windows.md` §2, §6, §9); ниже — только то, что на Linux своё.

Пункты с пометкой **(предложено)** Олег ещё не подтверждал. Пункты с пометкой **(проверить)** надо подтвердить на настоящей системе на этапе 0.

---

## 1. Цель и границы

- **Первая очередь:** Ubuntu 24.04 и новее (GNOME), Fedora Workstation (GNOME), KDE Plasma 6 (Kubuntu, Fedora KDE, openSUSE). x86-64 и ARM64, Wayland и X11.
- **Остальные окружения** (Xfce, Cinnamon, sway, Hyprland и т. п.) — «как получится». Ничего специально для них не делаем, но и не ломаем.
- Без root: установка, работа и обновления — в домашней папке пользователя.
- Возможности — как у Mac-версии на момент начала работ.
- Claude Code на Linux работает родным образом. Из всех трёх систем это самый простой для него случай.

## 2. Технология

Tauri 2, общий код с Windows (SPEC-windows §2). На Linux интерфейс рисует WebKitGTK, значок в трее — через StatusNotifierItem (libayatana-appindicator).

## 3. Соответствие Mac → Linux

| На Mac | На Linux |
|---|---|
| Значок и текст в строке меню | Значок в трее через StatusNotifierItem; текст рядом — только где окружение его показывает (§4.1) |
| Панель под значком | Небольшое окно. На X11 — у значка; на Wayland место выбирает окружение (§4.2) |
| Токен из Связки ключей | Файл `~/.claude/.credentials.json`, тот же JSON `claudeAiOauth` **(проверить)**; не сохраняется и не пишется в журнал |
| `~/Library/Application Support/ClaudePult/` | Папки XDG (§6) |
| Hook на Python | Та же программа `claudepult-hook`, что на Windows, собранная для Linux (§4.3) |
| Терминал через AppleScript | Терминал по выбору, у каждого свой шаблон запуска (§4.4) |
| «Показать» по tty | Точно — в kitty, WezTerm, tmux, Konsole; в остальных — только окно, и то на X11 (§4.5) |
| `claude -p` в фоне, SIGTERM | Так же, как на Mac: POSIX-сигналы, свой сеанс через `setsid` |
| Уведомления | `org.freedesktop.Notifications` с кнопками |
| Ключи API в Связке ключей | Secret Service (libsecret): GNOME Keyring или KWallet |
| Вход в систему | `~/.config/autostart/claudepult.desktop` |
| Двойной клик по `.claudepult` | Тип файла `application/x-claudepult` и `.desktop`-файл с `MimeType` |
| Виджет | Не в первой версии; позже — виджет Plasma (§4.8) |
| `ClaudePult --usage` и другие команды | `claudepult --usage`: на Linux одна программа и печатает в консоль сама |
| `brew install …` | `npm i -g …` или официальные скрипты установки агентов; `brew` — если он есть |

## 4. Подробности

### 4.1 Значок в трее
- **KDE Plasma**: трей есть всегда. Видны иконка и подсказка; текст рядом с иконкой Plasma не показывает **(проверить)**.
- **Ubuntu (GNOME)**: в системе уже стоит расширение «Ubuntu AppIndicators». Оно показывает и иконку, и текст (`label`), так что строка «42 % · 2:14 · ✋1» возможна, почти как на Mac **(проверить)**.
- **Fedora и чистый GNOME**: трея нет без расширения «AppIndicator and KStatusNotifierItem Support». Поэтому:
  - при первом запуске помощник это проверяет и даёт ссылку на расширение;
  - без трея ClaudePult работает как обычное окно, а уведомления приходят как обычно.
- Рисованная иконка (кольцо или число процентов, точка ожидания) и подсказка — как на Windows (SPEC-windows §4.1). Текст рядом — где окружение его показывает. Вкладка «Строка меню» показывает только то, что работает в текущем окружении.

### 4.2 Панель
- **X11**: окно без рамки у значка, закрывается при потере фокуса.
- **Wayland** не даёт приложению ставить окно в нужную точку экрана. Поэтому:
  - панель открывается там, куда её поставит окружение (обычно по центру), и закрывается по Esc или при потере фокуса;
  - щелчок правой кнопкой по значку — короткое меню (лимиты одной строкой, сессии, ждущие ответа, «Открыть панель», «Настройки», «Выход»).
- Глобальное сочетание клавиш для панели (на Wayland — через портал GlobalShortcuts) — вторая волна.

### 4.3 Hooks и сессии
- Hooks — в `~/.claude/settings.json`, с резервной копией, как на Mac.
- `claudepult-hook` — та же программа на Rust, что на Windows: одинаковое поведение и формат файла сессии. Python есть почти везде, но версия и пути разные, а программа ни от чего не зависит.
- В файл сессии кроме PID Claude и tty (`/proc/<pid>/stat`) записываются переменные терминала из окружения — по ним «Показать» находит вкладку:
  - `TERM_PROGRAM`;
  - `KITTY_WINDOW_ID`, `KITTY_LISTEN_ON`;
  - `WEZTERM_PANE`;
  - `TMUX`, `TMUX_PANE`;
  - `KONSOLE_DBUS_SERVICE`, `KONSOLE_DBUS_SESSION`.
- Приложения Claude для компьютера на Linux официально нет **(проверить на момент работ)**, поэтому видны только сессии CLI. Если приложение появится — та же логика `claude://`, что на Mac.

### 4.4 Запуск Claude в терминале
- Терминала по умолчанию на Linux нет. ClaudePult ищет установленные терминалы и предлагает выбор в Настройках:
  1. `$TERMINAL`;
  2. Ptyxis (по умолчанию в новых Fedora и Ubuntu), GNOME Console (`kgx`), GNOME Terminal, Konsole, kitty, WezTerm, Alacritty, foot, xfce4-terminal;
  3. `x-terminal-emulator` в Debian и Ubuntu.
- У каждого терминала свой шаблон: папка, заголовок, команда. Например:
  - `gnome-terminal --working-directory=<папка> --title=<проект> -- <скрипт>`;
  - `konsole --workdir <папка> -e <скрипт>`;
  - `kitty --directory <папка> --title <проект> <скрипт>`;
  - `wezterm start --cwd <папка> -- <скрипт>`.

  Каждый шаблон проверяется на этапе 0.
- Задача, как и на Windows, передаётся через временный файл, а не в командной строке.
- Если ClaudePult запущен внутри tmux, есть вариант «новое окно tmux» (`tmux new-window -c <папка>`).
- Worktree — как на Mac.

### 4.5 «Показать»
Зависит от терминала. В интерфейсе написано, что получится в выбранном терминале.

| Терминал | Что делает «Показать» |
|---|---|
| kitty | точно: `kitty @ focus-window --match id:<KITTY_WINDOW_ID>` (нужно `allow_remote_control` — помощник подскажет) |
| WezTerm | точно: `wezterm cli activate-pane --pane-id <WEZTERM_PANE>` |
| tmux | точно: `tmux switch-client` / `select-window` / `select-pane` по `TMUX_PANE` |
| Konsole | вкладка через D-Bus (`KONSOLE_DBUS_SERVICE`, `KONSOLE_DBUS_SESSION`) **(проверить)** |
| GNOME Terminal, Ptyxis, остальные | на X11 — окно терминала по `_NET_WM_PID` (вкладку выбирает человек); на Wayland — только уведомление «Сессия в <терминал>, папка <проект>» |

- Окно ClaudePult не может вывести вперёд окно другого приложения на Wayland — это ограничение GNOME и KDE, не наше. В таблице выше это уже учтено.

### 4.6 Фоновые задачи
- Как на Mac:
  - `claude -p …` в своём сеансе (`setsid`), чтобы задача пережила выход из ClaudePult;
  - остановка — SIGTERM, через 10 с SIGKILL.
- Журнал — `~/.local/state/claudepult/runs/<id>.log`.
- Правила разрешений — как на Mac. Пути в запретах: `~/.ssh`, `~/.gnupg`, `~/.config/claudepult`, `.env`.

### 4.7 Проекты, команды, календарь
- Без изменений. Папка проектов по умолчанию — `~/Projects`.
- `git` из системы. Если `gh` нет, помощник даёт команду установки для этого дистрибутива (`apt`, `dnf`, `zypper`).
- Модуль «Отчёты `_daily-report`» — если папка найдена и есть `python3`. «Очистка» скрыта: `cleanup.py` рассчитан на Mac.

### 4.8 Виджет
- На Linux общего механизма виджетов нет.
- **(предложено)** Позже: виджет Plasma (QML), который читает `usage.json`. Для GNOME — ничего, ему хватит значка и подсказки.

### 4.9 Модули из SPEC-profiles

- **«Ресурсы компьютера» (предложено)**:
  - процессор — `/proc/stat`;
  - память и давление памяти — `/proc/meminfo`, `/proc/pressure/memory`;
  - диск — `statvfs`;
  - сеть — `/proc/net/dev`;
  - батарея — `/sys/class/power_supply`;
  - графика — `/sys/class/drm/*/device/gpu_busy_percent` для AMD и Intel, `nvidia-smi` при наличии;
  - процессы — `/proc/<pid>/stat`.

  Клик — системный монитор окружения (`gnome-system-monitor`, `plasma-systemmonitor`).
- **«Не спать»**:
  - сон — блокировка через logind (`org.freedesktop.login1.Manager.Inhibit`, `sleep:idle`);
  - экран — `org.freedesktop.ScreenSaver.Inhibit` или портал Inhibit.

  Правила те же. «С закрытой крышкой» (`handle-lid-switch`) logind может разрешить без root — тогда на Linux это первая волна **(проверить)**.
- **«Быстрые команды»**: скрипт shell, «открыть» (`xdg-open`). Ярлыков «Команд» нет.
- **«Быстрые переключатели»** — у каждого окружения свои. Показываются только те, что работают здесь:
  - тёмная тема — `gsettings set org.gnome.desktop.interface color-scheme prefer-dark` в GNOME, `plasma-apply-colorscheme` в KDE;
  - заблокировать — `loginctl lock-session`;
  - погасить экран — `kscreen-doctor --dpms off` (KDE), `xset dpms force off` (X11);
  - извлечь диски — `udisksctl unmount` и `power-off`;
  - очистить корзину — `gio trash --empty`, с подтверждением;
  - «скрыть значки на столе» — нет: в GNOME их и так нет.

## 5. Сервисы AI
- Агенты ищутся в PATH и в `~/.local/bin`, `~/.npm-global/bin`, `~/.bun/bin`.
- Ключи API — Secret Service, элемент «ClaudePult API key» с атрибутом провайдера.
- Если хранилища ключей нет (минимальные окружения без GNOME Keyring и KWallet), ключ не сохраняется, а ClaudePult объясняет, что поставить. Открытым текстом ключи не храним **(предложено)**.

## 6. Данные и файлы (XDG)

| Что | Где |
|---|---|
| Настройки, профили, модули | `~/.config/claudepult/settings.json` |
| `usage.json`, `api-spend.json` | `~/.local/share/claudepult/` |
| Файлы сессий | `~/.local/state/claudepult/sessions/` |
| Журналы фоновых задач, журнал приложения | `~/.local/state/claudepult/runs/`, `~/.local/state/claudepult/logs/` |
| Связь с запущенным приложением | сокет `$XDG_RUNTIME_DIR/claudepult.sock` |

- Учитываются `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, если заданы.
- Файл `.claudepult` — тот же формат версии 2, что на Mac и Windows (SPEC-windows §6). Модули, которых на Linux нет, сохраняются и показываются как «недоступно на Linux».

## 7. Установка и обновления
- **AppImage** — один файл для любого дистрибутива. Обновляется встроенным в Tauri механизмом с GitHub Releases. При первом запуске ClaudePult предлагает:
  - положить себя в `~/.local/bin`;
  - создать `.desktop`-файл и тип `.claudepult`.
- **.deb и .rpm** — для тех, кто ставит через пакеты. Обновления у них — новыми пакетами.
- **Flatpak — не делаем (предложено).** Песочница мешает самому нужному:
  - запускать `claude`, `git`, терминалы;
  - читать `~/.claude`;
  - видеть процессы.

  Всё это пришлось бы делать через `flatpak-spawn --host`, и смысл песочницы пропадает.
- Подпись: Linux её не требует. Релизы подписываются ключом обновлений Tauri; GPG-подпись файлов — по желанию.

## 8. Чего не делать
- Не просить root и не ставить системные службы.
- Не подстраиваться под каждое окружение: первая очередь — GNOME и KDE (§1).
- Не обещать в интерфейсе того, что в этом окружении не работает (трей, текст у значка, «Показать»).
- Без телеметрии. Не копировать код GPL-проектов. Mac-версию ради Linux не трогать.

## 9. Этапы
Те же, что для Windows (SPEC-windows §9), и делаются вместе с ними. Отличия:
- **Этап 0** — в виртуальных машинах на Mac (UTM, ARM64): Ubuntu 24.04 и Fedora с KDE. Проверить:
  - токен Claude Code;
  - трей и текст у значка в GNOME (Ubuntu) и в Plasma;
  - шаблоны терминалов;
  - «Показать» в kitty, WezTerm, tmux, Konsole;
  - logind для крышки;
  - Secret Service.
- **Этап 7** — AppImage, .deb, .rpm вместо установщика Windows.
- Этапа WSL нет.

Сборка x86-64 для пользователей — в виртуальной машине x86-64 или на сборочном сервере. Это решится вместе с CI.

# ClaudePult для текстов — техзадание (черновик на обсуждение)

Основное ТЗ — `docs/SPEC.md` (пульт программиста). Этот документ описывает второй режим: для людей, которые пишут в Claude тексты — сценарии для видео, посты, статьи, рассылки. Код, комментарии, коммиты, STATUS — на английском, интерфейс — на русском, как и везде.

Статус: **черновик**. Разделы «Открытые вопросы» нужно решить с Олегом до начала работы.

---

## 1. Зачем

Сейчас ClaudePult полезен только программисту: проекты — это git-репозитории из `report.py`, команды Claude — про ветки, проверки и PR, сессии — только Claude Code. Автор текстов из этого видит лишь лимиты подписки.

При этом Claude Code одинаково хорошо работает с обычными текстовыми файлами, а у фонового режима уже есть нужное: запуск без окна, правки только внутри папки, итог уведомлением и в Telegram, очередь «после сброса лимита». Нужно дать автору текстов свою модель проекта и свои команды.

**Кто это:** человек ведёт YouTube-канал или блог, пишет сценарии и тексты с Claude, держит материалы в папках на Маке. Git не знает и знать не должен. Работает урывками и упирается в лимиты.

**Что он получит:**
- видит все свои ролики/тексты и на каком они этапе;
- одной кнопкой просит Claude сделать типовую работу над текстом, результат появляется файлом рядом;
- длинные задачи ставит в фон или «после сброса лимита» и узнаёт об итоге уведомлением;
- не теряет удачные версии черновиков.

## 2. Что уже есть и переиспользуется

- Лимиты подписки, прогноз, уведомления, виджет (SPEC §2.8) — без изменений.
- Фоновый запуск `claude -p` с правами, журналом, лимитом времени, итогом (SPEC §2.4) — для текстов нужен свой, более узкий набор прав (§4.4).
- Очередь «запустить после сброса», уведомления с переходом по клику, Telegram.
- Настройки и «Внешний вид».

## 3. Что меняется в основе

1. **`_daily-report` и git необязательны.** Сейчас без `report.py` список проектов пуст. Источник проектов становится подключаемым: «Код» (как сейчас, `report.py`) и «Тексты» (папки, §4.1). Можно включить один или оба.
2. **Режим в настройках** (Основные): «Код», «Тексты», «Оба». От режима зависят блоки панели и команды в проекте.
3. **Сессии и hooks** остаются для тех, кто пользуется Claude Code. Обычные чаты claude.ai / приложения Claude ClaudePult не видит (нет локальных данных и API) — это честно написать в «Помощи».

## 4. Режим «Тексты» — первая версия

### 4.1 Проект = папка

- Папка текстов в настройках (по умолчанию `~/Documents/Тексты` — уточнить), каждая подпапка — проект (ролик, статья).
- Внутри — любые файлы; учитываются `.md`, `.txt`, `.rtf`, `.docx` (только чтение `.docx` — уточнить).
- Карточка проекта хранится в `проект.md` внутри папки (человекочитаемо, можно править руками):

```markdown
# Как выбрать первый микрофон
Этап: черновик
Дедлайн: 2026-11-05
Формат: YouTube, 8–10 мин
Главный файл: сценарий.md
```

- Этапы по умолчанию: идея → ресёрч → черновик → монтажный лист → опубликовано (список настраивается).

### 4.2 Строка и карточка проекта в панели

- Строка: этап (цветная метка), название, дедлайн («через 3 дня», красным если просрочен), слов в главном файле и **хронометраж** (по умолчанию 150 слов/мин, настраивается), когда меняли.
- Раскрытие: этап (смена прямо из панели), формат, список файлов, кнопки «Открыть папку», «Открыть главный файл», шаблоны задач (§4.3), последние результаты.

### 4.3 Шаблоны задач

Готовые задачи в один клик над проектом или выбранным файлом. Шаблон — это название, промт с подстановками и куда класть результат.

Встроенные (можно править и добавлять свои в настройках):

| Шаблон | Что делает | Результат |
|---|---|---|
| Хуки | 3–5 вариантов первых 5–10 секунд | `хуки.md` |
| Сократить для Shorts | версия на 60 с (~150 слов) | `сценарий-shorts.md` |
| Описание YouTube | описание, таймкоды по заголовкам, теги | `описание.md` |
| Заголовки | 10 вариантов названия + 3 идеи обложки | `заголовки.md` |
| Проверка фактов | пометить спорные утверждения, что проверить | `факты.md` |
| Перевод | перевод на выбранный язык с сохранением тона | `сценарий-en.md` |
| Своя задача… | свободный текст | `результат-<время>.md` |

Подстановки в промте: `{файл}`, `{проект}`, `{формат}`, `{хронометраж}`, `{текст}` (свободный ввод).

Запуск — через фоновый режим (§4.4). Результат никогда не перезаписывает существующий файл: при совпадении имени добавляется `-2`, `-3`.

### 4.4 Права в фоне для текстов

Уже, чем для кода:
- разрешено: читать и создавать/править файлы **только внутри папки проекта**;
- запрещено: любые команды Bash, сеть (кроме, возможно, поиска для «Проверки фактов» — открытый вопрос), удаление файлов, всё вне папки.

Проверить вживую так же, как в этапе 5 (набор разрешённых и запрещённых действий на тестовой папке).

### 4.5 Версии черновиков

- Перед каждой фоновой задачей и раз в N минут, если файлы менялись, — снимок папки проекта.
- Хранить в скрытой папке `~/Library/Application Support/ClaudePult/versions/<проект>/` (под капотом git, пользователь его не видит), а не в самой папке проекта.
- В карточке: «Версии» → список по времени → «Сравнить» / «Вернуть эту версию» (возврат тоже делает снимок, ничего не теряется).

## 5. Позже (не в первой версии)

- **Быстрый запрос из любого приложения:** выделить текст → сочетание клавиш → «усиль / упрости / другой тон / короче» → результат в буфер обмена. Нужны разрешение «Универсальный доступ» и аккуратная работа с буфером.
- **Пакетные задачи:** один шаблон на несколько проектов («описания для 10 роликов»), с запуском ночью или после сброса лимита.
- **Календарь публикаций** по дедлайнам, уведомление за день.
- Импорт/экспорт в Google Docs или Notion.

## 6. Чего не делать

- Не читать и не отправлять тексты никуда, кроме Claude Code, запущенного у пользователя.
- Не трогать файлы вне папки проекта; не перезаписывать файлы пользователя.
- Не ломать режим «Код»: для Олега всё работает как сейчас.

## 7. Открытые вопросы (решить с Олегом)

1. Для кого делаем: только для Олега (ведёт ли он тексты сам?) или для других людей? Если для других — нужны подписка разработчика Apple и нотаризация (сейчас подпись локальная), английский интерфейс, онбординг без `_daily-report`.
2. Где лежат тексты у реальных пользователей: обычные папки, iCloud Drive, Google Drive, Notion? От этого зависит §4.1.
3. Формат файлов: только Markdown/текст или нужен `.docx`/Pages?
4. Разрешать ли «Проверке фактов» поиск в интернете (WebSearch) в фоне?
5. Набор этапов и шаблонов по умолчанию — показать 2–3 знакомым авторам до разработки.
6. Название режима в интерфейсе: «Тексты», «Контент», «Сценарии»?

## 8. Этапы (после решения вопросов)

1. **Основа:** источники проектов подключаемые, режим в настройках, ClaudePult работает без `_daily-report`.
2. **Проекты-папки:** `проект.md`, этапы, дедлайны, слова и хронометраж, карточка в панели.
3. **Шаблоны задач:** встроенные + свои, фон с правами для текстов (проверка прав вживую), результат файлом рядом.
4. **Версии черновиков.**
5. **Быстрый запрос** и пакетные задачи — по итогам первых четырёх.

Каждый этап — как в основном ТЗ: ветка, проверки, установка, проверка вживую, STATUS, PR.

# ClaudePult — техзадание

Нативное macOS-приложение в строке меню (иконка сверху, без Dock): пульт для проектов в `~/Projects` и для сессий Claude Code, которых у Олега часто запущено несколько одновременно.

Владелец: Олег. Общается по-русски. Интерфейс приложения — на русском. Код, комментарии, коммиты, `docs/STATUS.md` — на английском. Общие правила работы — `~/Projects/CLAUDE.md` (обязательны).

---

## 1. Окружение и то, что уже есть

- Mac на Apple Silicon, macOS 27 (на момент этапа 1 — macOS 27.2, Xcode 27.1, Swift 6.4; минимальная цель приложения — macOS 14). Xcode установлен. Homebrew в `/opt/homebrew`.
- `~/Projects/<проект>` — git-репозитории: Ambo, Cantero, MeisterHub, Survikon, zustellos (список меняется, приложение находит проекты само).
- `~/Projects/CLAUDE.md` — общие правила для Claude Code во всех проектах (STATUS.md, ветки, PR, merge делает только Олег, worktree только в `.claude/worktrees/`).
- `docs/STATUS.md` в каждом проекте: шапка между `<!-- summary:start -->` и `<!-- summary:end -->` с полями `**Stage:**`, `**Updated:**`, `**Now:**`, `**Next:**`, `**Needs Oleh:**` + журнал записей `## YYYY-MM-DD — …` (новые сверху).
- `~/Projects/_daily-report/` — Python-инструменты (не git):
  - `report.py --json --no-fetch` — **источник данных о проектах для ClaudePult** (формат ниже). Логику git/STATUS не дублировать в Swift — вызывать этот скрипт. С `--no-fetch` отрабатывает за несколько секунд; без него делает `git fetch` (медленнее, раз в 30 мин достаточно).
  - `report.py --since-hours N --no-open` — полный отчёт с AI-резюме, шлёт в Telegram (1–3 мин).
  - `report.py --no-ai --no-document --no-open --since-hours N` — быстрая сводка в Telegram.
  - `cleanup.py --dry-run` / `cleanup.py --now` — очистка сборок (вывод — текст, первая строка — итог).
  - `config.json` — там `telegram.bot_token` и `telegram.chat_id` (использовать для уведомлений; файл не коммитить никуда, секреты не логировать).
  - `help.txt` — список всех команд для `/help` Telegram-бота (Telegram HTML: `<b>`, `<code>`, ≤ 4000 символов). Новые команды ClaudePult дописать туда.
  - Бот (`bot.py`) и launchd-агенты `com.demishev.projects-*` уже работают — не трогать, не конфликтовать.

### Формат `report.py --json` (version 1)

```json
{
  "version": 1, "generated": "ISO", "since": "ISO", "disk_free_bytes": 123,
  "other_folders": ["reports", "sales"],
  "projects": [{
    "name": "Cantero", "path": "/Users/…/Projects/Cantero",
    "branch": "claude/x", "default_branch": "origin/main", "remote": "https://github.com/…",
    "health": "red|yellow|green",
    "last_activity": "ISO|null", "dirty": 21, "dirty_sample": ["apps/…"], "stashes": 1,
    "commits": [{"hash": "abc1234", "subject": "…", "ref": "origin/feat/x", "date": "ISO"}],
    "merged_prs": [{"number": 4, "branch": "claude/x"}],
    "open_prs": [{"number": 5, "title": "…", "headRefName": "…", "isDraft": false, "url": "…", "ci": "ok|fail|pending|none"}] ,
    "local_only": [{"branch": "x", "commits": 2}], "unpushed": [{"branch": "x", "commits": 1}],
    "worktrees": [{"path": "…", "branch": "…", "dirty": 3}],
    "attention": [{"level": "high|mid|low", "text": "по-русски"}],
    "status": {"path": "docs/STATUS.md",
               "summary": {"stage": "…", "updated": "…", "now": ["…"], "next": ["…"], "needs": ["…"]} ,
               "latest_entry": {"date": "YYYY-MM-DD", "title": "…"}}

```
`open_prs` = `null`, если нет `gh`; `status` = `null`, если нет STATUS.md; `summary` = `null`, если нет шапки. Поля могут добавляться — декодировать терпимо (неизвестные поля игнорировать, отсутствующие — опциональны).

## 2. Что должно уметь приложение

### 2.1 Иконка и меню
- Иконка в строке меню (SF Symbol) с цветной точкой общего состояния: красная, если у любого проекта `health = red`; бейдж с числом сессий, ждущих ответа Олега.
- По клику — панель (SwiftUI `MenuBarExtra` со стилем `.window`), ширина ~420 pt:
  1. Блок **«Сессии»** (раздел 2.3) — сверху, если есть активные.
  2. Список **проектов** (раздел 2.2).
  3. **Общие команды** (раздел 2.5) + свободное место на диске.
  4. Внизу: «Настройки…», «Помощь», «Выход».

### 2.2 Проекты
- Строка проекта: точка `health`, имя, ветка, число незакоммиченных файлов, «N мин/ч/дн назад», значок открытых PR (с цветом CI).
- Раскрытие проекта: `Stage`, `Now`, `Next`, `Needs Oleh` из шапки STATUS.md; список `attention`; кнопки:
  - **Claude: следующий шаг**
  - **Claude: своя задача…**
  - **Claude: завершить сессию**
  - Открыть в Терминале / Finder / на GitHub (`remote` → https).
- Данные обновляются: при открытии панели (если старше 60 с), фоном каждые 5 мин (`--no-fetch`), раз в 30 мин — с fetch. Обновление не блокирует UI.

### 2.3 Сессии Claude Code
Показывать **все** сессии Claude Code на этом Маке — и запущенные из ClaudePult, и запущенные Олегом вручную.
- Источник — **hooks Claude Code** в пользовательских настройках (`~/.claude/settings.json`): небольшой скрипт-хук, который на событиях начала сессии, отправки промта, уведомления (Claude ждёт ответа/разрешения), остановки и конца сессии пишет JSON-файл `~/Library/Application Support/ClaudePult/sessions/<session_id>.json`: `session_id`, `cwd`, проект (по `cwd` внутри `~/Projects`), событие, состояние, время, последний промт (первые 200 символов), `transcript_path`. Перед реализацией сверить актуальные названия событий и формат входных данных hooks в документации Claude Code (агент claude-code-guide / docs.claude.com) — не по памяти.
- Установка hooks: **сливать** с существующим `~/.claude/settings.json` (не перезаписывать, сначала сделать бэкап рядом), идемпотентно; кнопка «Установить/обновить hooks» в настройках и снятие их там же.
- Состояния: `работает`, `ждёт ответа` (уведомление от Claude), `готово` (остановка), `завершена`, `ошибка` (только фоновые). Сессия без событий > 2 ч и без живого процесса — скрывать как устаревшую.
- Строка сессии: проект, worktree/ветка, начало задачи, длительность, состояние. Действия: «Показать» (для терминальных — вывести окно Терминала на передний план, если можно определить; иначе открыть папку), для фоновых — «Журнал» и «Остановить».
- Ждущие ответа сессии подсвечены и дают уведомление macOS один раз.

### 2.4 Запуск Claude: два режима
Каждая команда из 2.2 спрашивает (или берёт из настроек по умолчанию) режим: **Терминал** или **Фон**. Опция «Запомнить выбор».

Промты (подставляются как есть, `{task}` — текст Олега):
- **Следующий шаг:** «Прочитай только шапку docs/STATUS.md и последнюю запись журнала. Возьми первый пункт из Next и выполни его по правилам ~/Projects/CLAUDE.md: отдельная ветка от origin/main, проверки проекта, коммит, push, PR, запись в STATUS.md и обновление шапки. Если пункт требует решения Олега или неясен — ничего не меняй, а запиши вопрос в Needs Oleh и закончи.»
- **Своя задача:** «Задача от Олега: {task}. Работай по правилам ~/Projects/CLAUDE.md: отдельная ветка от origin/main, проверки, коммит, push, PR, запись в STATUS.md.»
- **Завершить сессию:** «Заверши текущую работу в этой папке по разделу "Конец сессии" из ~/Projects/CLAUDE.md: проверки, коммит, push, PR, запись в STATUS.md и шапка. Новых изменений кода не делай. Если незакоммиченные изменения относятся к разным задачам — разнеси их по отдельным веткам и PR.»

**Терминал:** открыть новое окно Terminal.app в папке проекта (или worktree) и запустить там `claude` с промтом как первым сообщением (через AppleScript `do script`; корректно экранировать кавычки/переводы строк). Приложению понадобится разрешение Automation для Terminal — запросить понятно, объяснить в UI.

**Фон:** `claude -p` в папке проекта/worktree, вывод — в stream-json, журнал в `~/Library/Application Support/ClaudePult/runs/<id>.log`; по завершении — уведомление macOS и сообщение в Telegram: «✅/❌ <Проект>: <начало задачи> — <итог в 1–3 строки, ссылка на PR если есть>» (Telegram HTML, токен из `_daily-report/config.json`; если не настроен — только уведомление). Флаги CLI сверить с `claude --help` на этой машине.

Права в фоне (никто не нажмёт «разрешить»), задать через флаги/настройки запуска, проверить по документации:
- разрешено: чтение/поиск/правка файлов внутри папки проекта; запуск проверок и сборок проекта (npm/pnpm/npx/bun, mvn, xcodebuild, gradle, expo, pytest и т.п.); `git status/diff/log/add/commit/checkout -b/switch/fetch/push` в **не-main** ветки; `gh pr create/view/list`.
- запрещено: push в `main`/`master`, `git push --force`, `git reset --hard`, `gh pr merge`, удаление файлов вне проекта, `sudo`, чтение/вывод `.env` и ключей.
- лимит времени фоновой задачи — 90 мин (настраивается), затем остановить и сообщить.

**Параллельность:** если в папке проекта уже есть активная сессия (по данным hooks) — новая запускается в worktree `<проект>/.claude/worktrees/cb-<короткий-slug>` с новой веткой от `origin/main` (имя ветки по смыслу задачи). Сообщить об этом в UI. Старые worktree не удалять автоматически — показать в проекте с кнопкой «Удалить worktree» (только если в нём нет незакоммиченного и ветка запушена).

### 2.5 Общие команды
- **Отчёт сейчас** (AI, в Telegram), **Быстрая сводка** (без AI), **Открыть последний отчёт** (`~/Projects/_daily-report/reports/latest.html`), **Очистка: проверить** (показать вывод `cleanup.py --dry-run` в окне), **Очистка: выполнить**. Длинные операции — со спиннером, не блокируя меню; результат — уведомлением.
- Свободное место на диске (из JSON) с предупреждением, если меньше 20 ГБ.

### 2.6 Настройки (отдельное окно `Settings`)
Папка проектов (по умолчанию `~/Projects`), путь к `_daily-report`, путь к `claude` (автопоиск: `/opt/homebrew/bin`, `~/.local/bin`, `~/.claude/local`), режим запуска по умолчанию, Telegram для фоновых задач вкл/выкл, лимит времени фоновой задачи, автозапуск при входе (`SMAppService.mainApp`), установка/снятие hooks.

### 2.7 Помощь
Пункт «Помощь» открывает окно со списком всех команд ClaudePult. Эти же команды дописать отдельным блоком `<b>🖥 ClaudePult</b>` в `~/Projects/_daily-report/help.txt` (не ломая остальное и лимит 4000 символов).

### 2.8 Лимиты подписки — паритет с Usage4Claude, своя реализация

Повторяем функционал открытого приложения Usage4Claude (github.com/f-is-h/Usage4Claude, MIT) **на нашем стеке**: Swift 6, async/await, SwiftUI, без Combine и сторонних зависимостей. Код не копируем, пишем сами; их приложение и README — только ориентир по поведению. Если всё же переносится заметный фрагмент кода — сохранить их уведомление MIT в `THIRD_PARTY_NOTICES.md`.

**Что показываем** — до пяти лимитов одновременно, для планов Free / Pro / Team / Max (что пришло в ответе, то и показываем):
- 5-часовая сессия, 7 дней по всем моделям, 7 дней Opus, 7 дней Sonnet, Extra usage (включён ли, потрачено/лимит, если есть);
- у каждого: % использования, время сброса и обратный отсчёт с точностью до минуты («через 2 ч 14 мин»; для недели — день и время).

**Источники данных** (реализовать оба, выбор в настройках, по умолчанию — первый доступный):
1. **Токен Claude Code** — `GET https://api.anthropic.com/api/oauth/usage`, заголовки `Authorization: Bearer <access token>` и `anthropic-beta: oauth-2025-04-20`. Токен читается из Keychain, элемент `Claude Code-credentials` (только чтение; у себя не хранить, не логировать; если истёк — «Войдите в Claude Code: `claude` → `/login`», сам токен не обновлять). Ответ: окна `five_hour`, `seven_day`, `seven_day_opus` / `seven_day_sonnet` (опционально), `extra_usage`; у окна `utilization` и `resets_at` (UTC).
2. **Вход через встроенный браузер** (как в Usage4Claude): окно с `WKWebView` на claude.ai, пользователь входит обычным способом, приложение берёт cookie `sessionKey` и список организаций и запрашивает их использование (эндпоинты claude.ai выяснить вживую по запросам самой страницы использования). `sessionKey` и id организации хранить **в своём** элементе Keychain. Ключ истёк — понятное «Войдите снова».

Оба способа **Anthropic не документирует**: проверить ответы вживую, декодировать терпимо (неизвестные поля игнорировать, отсутствующие считать опциональными). При ошибке или смене формата не падать — показать «Лимиты недоступны: <причина>» и записать в DECISIONS. Перед первым чтением токена Claude Code или открытием входа объяснить пользователю, что и зачем читается, и спросить согласие.

**Несколько аккаунтов и организаций:** список аккаунтов в настройках (добавить / переименовать / удалить), переключатель активного в панели; если у аккаунта несколько организаций — выбор.

**Строка меню, режимы отображения** (настройка): только иконка с цветом / % сессии / % сессии и недели / кольцо-индикатор. Цвет по самому заполненному лимиту: зелёный < 50 %, оранжевый 50–80 %, красный > 80 % (пороги настраиваются).

**Панель, блок «Лимиты»** сверху: полоски по всем лимитам из ответа, обратные отсчёты, время последнего обновления, кнопка «Обновить».

**Обновление:**
- **умное** (по умолчанию): интервал 1 → 3 → 5 → 10 мин. Замедляется, пока проценты не меняются, и возвращается к 1 мин, как только они растут или появилась активная сессия Claude (2.3). Сразу после `resets_at` — внеочередная проверка, чтобы быстро показать новые значения;
- **фиксированное**: интервал на выбор (1, 3, 5, 10, 30 мин);
- ручное — кнопкой; после пробуждения Мака — сразу.

**Уведомления macOS:** при достижении порога (по умолчанию 90 %, можно добавить 50 и 80 %) — один раз на окно лимита; «Лимит восстановлен» после сброса, если был выше порога. Включаются по каждому лимиту отдельно.

**Языки:** все строки через String Catalog; русский и английский сразу, украинский и немецкий — в этапе публичного релиза.

**Приватность:** всё локально, никаких сторонних серверов и телеметрии; секреты только в Keychain.

### 2.9 Лимиты+ — то, чего нет у аналогов

- **Прогноз:** по темпу за последние 30 мин — «хватит до ~16:40» или «до сброса хватит».
- **Разбивка по проектам:** из локальных журналов Claude Code (`~/.claude/projects/**/*.jsonl`, поле `usage` у сообщений ассистента: input/output/cache-токены, модель, путь сессии) — токены за текущую 5-часовую сессию, сегодня и неделю по проектам из папки проектов и по сессиям; топ проектов и самая «дорогая» сессия. Формат не документирован — парсить терпимо. Подписать как оценку распределения, а не точный расход лимита.
- **Защита фонового режима (2.4):** если сессия > 90 % — предупредить и предложить «Запустить после сброса» (очередь, старт в `resets_at` + 2 мин).
- **`usage.json`:** текущие значения в `~/Library/Application Support/ClaudePult/usage.json` (`five_hour`, `seven_day`, `updated`), чтобы отчёт и бот могли их прочитать позже. Изменения в `report.py`/`bot.py` — только записью в Needs Oleh.
- **Telegram:** события порогов и сброса — по желанию, токен из `_daily-report/config.json`.
- **Виджеты** WidgetKit: малый — кольцо сессии, средний — сессия + неделя + сброс. Если усложняют сборку — отложить в Next.

## 3. Технические требования

- Swift 6, SwiftUI, `MenuBarExtra`, `LSUIElement = YES`. Без сторонних зависимостей, если можно обойтись.
- Проект описан в `project.yml` (XcodeGen: `brew install xcodegen`), `.xcodeproj` генерируется и в git не коммитится. Если XcodeGen не подходит — объяснить в DECISIONS и выбрать другой воспроизводимый способ.
- `scripts/build-and-install.sh`: сборка Release через `xcodebuild`, копирование в `~/Applications/ClaudePult.app`, перезапуск приложения. Подпись — локальная (ad-hoc / личная команда), без App Store и нотаризации (нотаризация — вопрос этапа 11).
- Без App Sandbox (нужен доступ к `~/Projects`, запуск процессов, AppleScript Terminal). Hardened Runtime по необходимости.
- Все внешние процессы — асинхронно (`Process` + async/await), с таймаутами; UI никогда не ждёт синхронно.
- Пути к файлам и секреты не хардкодить — из настроек; токен Telegram только читается из `_daily-report/config.json`.
- Логи приложения — `~/Library/Logs/ClaudePult/`.
- Тесты (XCTest/Swift Testing) для чистой логики: декодирование JSON отчёта, разбор событий hooks и состояния сессий, экранирование команд для AppleScript, выбор папки/worktree, формирование промтов и Telegram-сообщений.
- Документация: `README.md` (что это, установка, команды), `DECISIONS.md` (решения, где ТЗ молчит), `docs/STATUS.md` по формату из `~/Projects/CLAUDE.md`.
- Репозиторий: `OlehDemishev/ClaudePult` на GitHub (пока приватный).

### 3.1 Готовность к публичной раздаче (соблюдать с этого момента на всех этапах)

Приложение будет бесплатно раздаваться другим людям, поэтому:
- **Никаких зашитых путей и личных данных.** Папка проектов, путь к `_daily-report`, Telegram — настройки. Интеграции с `_daily-report` (отчёт, очистка, `report.py --json`) и Telegram **необязательные**: если их нет, соответствующие пункты меню скрыты, а приложение работает. Без `report.py` список проектов работает в базовом режиме на Swift (git-репозитории в папке, ветка, незакоммиченное, шапка STATUS.md при наличии); с `report.py` — в полном.
- **Все строки интерфейса** — через String Catalog (ru + en).
- **Явное согласие** перед чтением токена Claude Code, входом в claude.ai, установкой hooks в `~/.claude/settings.json` и управлением Терминалом. Всё обратимо из настроек.

# AI Hub Bar — reference

> Formerly **ClaudePult** (renamed 2026-10-30; the GitHub repository is now `OlehDemishev/AIHubBar`). The Xcode project is `AIHubBar.xcodeproj` since 2026-11-03; the bundle id `com.demishev.claudepult` and the data folders (`~/Library/Application Support/ClaudePult`, `~/Library/Logs/ClaudePult`) keep the old name, so settings, macOS permissions and Keychain items carry over. The app is `~/Applications/AI Hub Bar.app`, the command line `~/Applications/AI\ Hub\ Bar.app/Contents/MacOS/AIHubBar`.

Native macOS menu bar app (no Dock icon): a control panel for the projects in `~/Projects` and for every Claude Code session on this Mac. **For people who just want to use it: [docs/GUIDE.md](GUIDE.md)** — what it does, install, first start, privacy, troubleshooting. This file is the reference for Oleh and for development (it was the README until the public README of 2026-10-31). ## What it does

Click ✦ in the menu bar. Next to it, by default: the subscription usage (5-hour session and week % — green < 50 %, orange 50–80 %, red > 80 %), a red dot when a project's health is red and ✋ with the number of Claude sessions waiting for an answer. What the menu bar shows is built in Settings → “Menu Bar” (presets, elements and their order, gauge style, separator, text size, colour; live preview).

**Limits** (top of the panel) — the 5-hour session with a countdown to the reset and a forecast from the last 30 minutes (“lasts until ~16:40” / “will last until the reset”), the week, per-model weeks, extra usage if enabled; “Usage by project” estimates each project's share and the heaviest session for the session / today / week from Claude Code's transcripts. Notifications once per window at 50/80/95 % (configurable) and when a limit is restored, optionally to Telegram. A background run while the session is above 90 % asks: start now or after the reset. Data from the same endpoint Claude Code uses (OAuth token read from the Keychain item “Claude Code-credentials”, never stored); current values are written to `~/Library/Application Support/ClaudePult/usage.json` (`five_hour`, `seven_day`, `updated`) for report.py and the bot.

**Sessions** (top of the panel, from Claude Code hooks) — every session on this Mac: Terminal, Claude desktop app, background runs. Project, worktree, task, duration, state (working / background / waiting / done / error / ended). Waiting sessions are highlighted and notify once. “Show” brings the session's Terminal tab forward (desktop-app sessions open that session in Claude, others the folder); background runs have “Log” and “Stop”.

**Projects** — from `~/Projects/_daily-report/report.py --json`: health, branch, uncommitted files, open PRs coloured by CI, last activity. A project expands into:

- **Claude**: “Next step” (first Next item), “Custom task…”, “Finish” — prompts from spec §2.4. Each asks **Terminal** (new Terminal window with `claude "<prompt>"`) or **Background** (`claude -p`, see below), or uses the default from Settings (“Remember”). If Claude already works in the project folder, the new task starts in a worktree `.claude/worktrees/cb-<slug>` on branch `claude/<slug>` from `origin/main`; “Finish” asks before a second session in the same folder.
- “Terminal / Finder / GitHub”.
- The STATUS.md header (Stage / Now / Next / Needs Oleh), attention items, open PRs.
- Worktrees with a delete button (only when clean and pushed or merged).

Data refreshes at launch, on panel open when older than 60 s, every 5 min (`--no-fetch`), every 30 min with `git fetch`, and with ⌘R.

**Commands** — through the `_daily-report` tools, with a spinner, a result line and a notification: “Report now” (AI report for 24 h to Telegram), “Quick summary” (no AI), “Latest report” (`reports/latest.html`), “Cleanup: check” (`cleanup.py --dry-run`, output in a window), “Cleanup: run” (`cleanup.py --now`, after a confirmation). Free disk space next to them, orange below 20 GB.

**Widget** “Claude limits” (right-click the desktop → “Edit Widgets…” → AI Hub Bar): small — session % ring with the reset countdown; medium — session and week bars. It reads `usage.json`, refreshed whenever AI Hub Bar updates the limits. A click opens a “Limits” window with the panel's limits block (`aihubbar://limits`; the panel itself can't be opened from code); ↻ asks the app to fetch the limits now without opening anything.

**Module options per profile:** in Settings → “Profiles” → “Panel” each profile chooses what it shows inside a module: “Mac Resources” — which metrics (“Metrics: 2 of 7”), “Quick Commands” — which buttons of the shared library, “Quick Toggles” — which toggles, “Keep Awake” — whether the 15 min / 1 h / 2 h timers show. Nothing chosen means everything, as before; the choices travel in `.claudepult` files (format 2, new keys are optional).

**Context fullness:** a session's row shows “context 85%” from 70 % (orange, red from 90 %), and at 90 % one notification per session: Claude will soon compact the history. Taken from the last main-thread assistant message in the session's journal (input + cache writes + cache reads); the window is 200 000 tokens, or 1 000 000 for “[1m]” models or once the context is past 200 000. Hooks don't report it.

**Night queue:** “Tonight” in a project's actions queues the next step (or, in “Custom task…”, your own task) as a background run at the night start hour (Settings → AI Services → Claude Code → “Background tasks”, 01:00 by default). Queued runs show in the limits card with “Cancel”. The Mac stays awake while they run (the “while Claude works” rule of “Keep Awake”), and when the night's runs are all done one summary arrives: “Overnight: 3 tasks — ✅ 2, ❌ 1” with a line per run, also in Telegram when “Result to Telegram” is on.

**Widget and Control Center:** a second widget “Sessions and projects” (small and medium): how many Claude sessions wait for an answer (and which), how many run, which projects are red. On macOS 26+ a Control Center control “Keep Awake (AI Hub Bar)” switches the manual keep-awake hold (needs the “Keep Awake” module). The app writes `widget-status.json` every 10 s when something changed and reloads the widget; the sandboxed control can't write the app's files, so it posts a Darwin notification (`com.demishev.claudepult.keepawake.on/off`) that AI Hub Bar listens for. The widget is clickable: the small one opens the one waiting session (or the search), the medium one links each row — waiting → that session (each project name → its own session), working and red projects → the search (`aihubbar://session/<id>`, `aihubbar://search`). With “Keep Awake” installed a ☕ button in its corner switches the same hold on any macOS 14+, without opening the app.

**Search, hot key, Shortcuts:** the panel has a search field under the header (sessions, projects, quick commands, report commands; ↵ runs the first match, Esc clears). ⌃⌥C (Settings → General: ⌃⌥C, ⌃⌥Space, ⌥⌘K or off) opens the same search as a small window in the middle of the screen from any app; there a project opens in Terminal, a session comes to the front. A query typed on the wrong keyboard layout (Cyrillic «ыгкм» for “surv”) matches too. The Shortcuts app gets three actions: “Claude limits” (returns the text, e.g. for Siri), “AI Hub Bar quick command” (runs a quick command by name) and “AI Hub Bar search”.

**Quick prompt** (optional AI module, Settings → Modules → “Quick Prompt”; docs/specs/SPEC-quick-prompt.md): a hot key in any app (⌃⌥P by default; ⌃⌥A, ⌃⇧Space or off on the module's page, registered only while the module is on) opens a small floating window: the task, the project, the agent and where it runs. The project starts as the one in front — the front window's document inside a project folder, or a project name in its title (Terminal, VS Code) — read only when Accessibility is already granted (“Keyboard Layout” asks for it; this module never does), else the last request's project, else the most recently active one. Claude Code (always the default) goes through the projects' own launch, like “Custom task…”: “Background” (`claude -p`) or “Terminal”, a worktree when Claude already works in the folder, the 90 % limit question and “Run anyway” shown in the window. Other installed agents open in Terminal in the project folder with the task on the clipboard (⌘V). ⌘↩ sends, Esc closes; the window closes by itself once the task is on its way and remembers the project and where it went. `AIHubBar --app-command quick-prompt` opens it too (with the module off it opens the module's page).

**Telegram bot** (optional AI module, Settings → Modules → “Telegram”; docs/specs/SPEC-telegram.md): one bot of your own from @BotFather, driven from a menu in the bot. Its page holds the token (only in the Keychain, `ClaudePult API key` / `telegram-bot`; “Use the _daily-report bot” copies `_daily-report/config.json`'s token and chat), “Link chat” (opens `t.me/<bot>?start=<code>`; the code lives 10 minutes; a chat id already set or the `_daily-report` one counts as linked), “This Mac answers the bot” (by default on for a desktop Mac, off for a laptop — only one Mac reads the bot's updates, every Mac still sends notifications; HTTP 409 from Telegram shows “Another Mac reads the bot” and retries every 60 s) and “Check” (sends the home menu). Only the linked private chat is answered; anything else is dropped silently. Commands (set with `setMyCommands`, the Menu button lists them): `/menu`, `/report [hours]` (AI report since the 10:00 morning report or for N hours, 0.25–168), `/status [hours]` (quick, no AI), `/clean check`, `/clean` (asks first), `/help` (plus “All Mac commands” = `_daily-report/help.txt`). A persistent menu sits at the bottom of the chat instead of the keyboard — 🏠 Home · 📊 Reports / 🧹 Mac · ❓ Commands: a press shows that screen as a new message and deletes the press and the screens before it (🏠 from the menu carries the menu itself, so it has no inline buttons). Inside a screen, its buttons edit that one message: 🏠 (this Mac, Claude session and week %, sessions working / waiting, background runs), 📊 Reports (AI since the morning, quick summary, AI for 1 / 3 / 24 h), 🧹 Mac (free disk, “What cleanup would delete”, “Clean up” → “Yes, clean up”). Reports and cleanup run `report.py` / `cleanup.py` in the `_daily-report` folder one at a time; `report.py` sends the report itself through the `config.json` bot. Messages older than 30 minutes are skipped; right after a gap of more than 30 minutes (the Mac slept, the app started) button presses only navigate. The send-only notifications of every module go through this bot when it is set (else through `config.json`'s); “Answers from Telegram” presses are handed over when the approvals bot is this same bot. **Bot menu** (Settings → Modules → Telegram → “Bot menu”): the buttons at the bottom of the chat are yours — the bot's screens and any quick command from the library (“▶️ name”), in your order (↑ ↓), 2 or 3 per row; 🏠 always stays. “Menu for” a profile with “This profile has its own menu” gives that profile its own buttons; switching to it sends 🏠 with them. “Update the menu in Telegram” sends 🏠 now. In the bot: ❓ Commands → ⚙️ “Set up the menu” switches buttons and the row width. A quick command pressed in the chat runs on this Mac (scripts and shortcuts up to 10 minutes; links, files, folders, apps and Terminal commands open on the Mac) and its result comes back; commands with “Ask before running” ask “Run?” in the chat. Over the shared bot they need “Quick commands over the shared bot” and always ask.

**Sessions, requests and limits in the bot** (stage 2): 🤖 Sessions lists the waiting sessions first, then the working ones (project, agent, what it waits for or does, how long ago), and the open permission requests numbered with ✅ n / ❌ n / ℹ️ n. With “Permission requests to this bot” on (the same setting as “Send permission requests to Telegram”), the Mac where Claude asks sends each request at once with “Allow” / “Deny” / “Details”; once answered anywhere the message loses its buttons and says how. The separate approvals bot then isn't used. Own bot: only the Mac that reads the bot offers the buttons; shared bot: a press goes back to the Mac that sent the message, and answering needs “Answers to requests over the shared bot”. ⏳ Limits shows every AI service of “AI Limits” with a bar per window, the reset and “at this pace runs out by …”, plus a switch for limit alerts to Telegram. Both screens are in the default bottom menu (🏠 🤖 / ⏳ 📊 / 🧹 ❓).

**Tasks from the bot** (stage 3): 🚀 Task lists the profile's projects (most active first); pick one, type the task as the next message (`/cancel` drops it), and it comes back with “Run” — then it starts like “Custom task…” in the background (Claude Code; a worktree when Claude already works in the folder, the 90 % question as buttons “Anyway” / “After the reset”). Below: running background tasks with 📜 (the last steps of the log) and ⏹ (asks first), and the last finished ones with their PR link — PRs are merged in GitHub, not from the bot. Over the shared bot this needs “Tasks over the shared bot”.

**Settings from the bot** (stage 4): ⚙️ Settings switches what comes to Telegram (background task results, limit thresholds, calendar reminders, PR and CI, permission requests, weekly summary — the same settings as the modules' “Telegram” chips), sets quiet hours (none, 22–08, 23–08, 00–09) and “Silence for 1 h”, and shows the morning report time read from `_daily-report`'s launchd agent (changed there, not here). Quiet hours and silence hold back alerts only; permission requests and the bot's replies still come. The same is on the module page, “Telegram alerts”. 🧹 Mac also turns “Keep Awake” on for an hour or off when that module is installed.

**Mini App** (shared bot only; docs/specs/SPEC-telegram.md §10): the bot's Menu button opens AI Hub Bar as a page inside Telegram — tabs 🏠 Home (Claude session and week rings, requests, sessions, background tasks, free disk), 🤖 Sessions (requests with Allow / Deny and the whole command), 🚀 Task (a project, a text field, “Run in the background”; running tasks with Log and Stop, finished ones with their PR), ⏳ Limits (every service, bars, resets, forecast), ••• More (reports, cleanup, “Keep Awake”, quick commands, Telegram alerts, quiet hours, silence). Telegram's colours and language (Russian or English). It is served by the relay at `/app`; every call carries Telegram's signed `initData`, which the relay checks with the bot token, and goes to the Mac that answers the chat; the same switches as the bot apply (answers, tasks and quick commands over the shared bot), dangerous actions ask first. A Mac that sleeps shows “💤 … is offline”. Settings → Modules → Telegram → “Where the menu is”: at the bottom of the chat and in the Menu button (default), or only in the Menu button (the keyboard at the bottom goes away). `/app?demo=1` shows sample data in a browser.

**Shared bot** (docs/specs/SPEC-telegram.md §7): the module's page offers “How to connect” — “Shared bot (quick)” (the default when no own token is set and the relay's address is known) or “Own bot (private)” (all of the above). The shared bot needs nothing from @BotFather: “Connect Telegram” opens the bot with a one-time code (10 minutes), “Start” pairs that chat with this Mac and the Mac greets it with 🏠. Each Mac registers once with the relay (`relay/telegram`, a Cloudflare Worker; its device key lives in the Keychain, `ClaudePult API key` / `telegram-relay`) and keeps one WebSocket to it, reconnecting after sleep; updates that came while it slept wait there for 24 hours. Several Macs can share a chat: one answers (the last paired, “This Mac answers the bot”, or `/macs` in the bot), all send notifications. The relay sends a Mac's calls only into its own chat and only `sendMessage`, `editMessageText`, `editMessageReplyMarkup`, `deleteMessage`, `answerCallbackQuery`, 30 a minute; it stores chat ↔ Mac ids and undelivered updates, never message text. “Disconnect” unpairs this Mac. The relay's address: `TelegramRelay.defaultURL`, or `defaults write com.demishev.claudepult telegramRelayURL https://…`. Later stages: sessions and requests, tasks and run control, limits, settings in the bot.

**PR and CI alerts:** when the project list refreshes (every 5 minutes, on panel open), a pull request whose CI turned red (“❌ CI failed: Cantero #41”), turned green again, or that is no longer open gets a notification; a click opens the PR. Optionally also to Telegram (the “Telegram” module's bot, else the `_daily-report` one). Settings → “Modules” → “Projects”. No data this time (no `gh`, offline) is never taken for “closed”.

**Answering from Telegram:** the same permission requests can go to Telegram as a message with “✅ Allow” / “❌ Deny” buttons (Settings → AI Services → Claude Code → “Answers from Telegram”). It needs a bot of its own — the `_daily-report` bot already reads its updates and two readers would take each other's — created with @BotFather; its token is kept in the Keychain (`ClaudePult API key` / `telegram-approvals`), the chat is the `_daily-report` one unless set. Only presses from that chat count; the buttons disappear once the request is answered anywhere.

**Week forecast:** under the limit rings, “the week runs out Sat 04:56 at this pace” (orange) or “the week lasts until it resets”, and small bars for each day of the current week window (today highlighted, hover for the day's share). The plan gives only the week's total; it is split over the days in the proportions of Claude Code's journals (the same weights as “Usage by project”), and the pace is the last 24 hours. One notification per week window when the pace says the week runs out before the reset.

**What Claude is doing now:** a working session's row shows its last tool call in words — “editing LimitsView.swift”, “running npm test”, “searching TODO” (the task moves to the hover hint). With no tool call for 10 minutes the time turns into an orange “quiet N min”. The hook keeps `last_tool`, `last_target`, `last_tool_at` from PostToolUse (written when the action changes, else once a minute; cleared on Stop).

**Answering Claude from AI Hub Bar:** when a Claude Code session asks for a permission (a command, a file edit), the notification and the session row in the panel get “Allow” / “Deny”. The hook writes `approvals/<id>.request.json` and waits up to 290 s for AI Hub Bar's answer; Claude's own dialog is on screen at the same time, so whichever answer comes first applies. The hook only waits while AI Hub Bar runs with the option on (Settings → AI Services → Claude Code, on by default); hooks installed before need “Update hooks” once (the PermissionRequest timeout grows from 5 to 300 s). In auto mode Claude rarely asks.

**Panel layout** (design variant A, chosen by Oleh 2026-10-30): every block sits on its own rounded card; the header holds the current profile (a menu when several are enabled) and icons for refresh (⌘R), Settings (⌘,), Help and Quit (⌘Q); the limits are two rings (session and week, colour by level, when each resets); sessions and projects are one line each (a project's branch shows only when it isn't `main`/`master`, a session's actions appear on hover); quick toggles are labelled tiles that light up when on. The “Dark” / “Light” panel theme now really applies (it is set on the panel window).

**Hover hints:** every control shown only as an icon has a hover hint; hovering over the menu bar item shows a summary of everything drawn in it (session and week, waiting, running, queued, reset countdown, forecast, nearest date, low disk, processor, memory, ☕, profile).

**Profiles** (SPEC-profiles; were “Modes”) — AI Hub Bar works in profiles made of modules: “AI limits”, “Agent sessions”, “Upcoming”, “Projects”, “`_daily-report` reports” (docs/specs/SPEC-profiles.md). A profile chooses which of its modules the panel shows and in what order (Settings → “Profiles” → “Panel”; “Upcoming”, “Projects”, “Reports” appear when the profile has the calendar on, a project source or `_daily-report`) and has its own menu bar (Settings → “Menu Bar” edits the current profile's). The current setup is the profile “Developer — Oleh”. With more than one profile enabled, a switcher appears at the top of the panel; Settings → “Profiles” lists them (enable, order, duplicate, export, import, delete). Optional modules are installed from Settings → “Modules” (“Install” also adds it to the current profile, “Remove” takes it out of every profile; a profile adds or drops it in “Panel”). The first one is **“Mac Resources”**: processor, memory and pressure, graphics, disk, network, battery and the five busiest processes — every 2 s while the panel is open and every 30 s otherwise, only while installed; alerts for processor above 90 % for 5 minutes, critical memory, low disk and battery below 15 %; “Processor” and “Memory” menu bar elements. CLI: `AIHubBar --resources`. The second is **“Keep Awake”**: a power assertion (`pmset -g assertions` shows “ClaudePult keep awake”; System Settings are not touched) while Claude works (a session or a background run — on by default), on power, with an external display or while chosen apps run; by hand the panel switch (“until switched off”) and 15 min / 1 h / 2 h timers; optionally the display too; ☕ in the menu bar. The “Developer” template ticks it in the assistant. **“Also with the lid closed”** (laptops only): a power assertion doesn't survive a closed lid, so AI Hub Bar runs `pmset -a disablesleep 1` while a rule holds and `0` afterwards, on quit, when the module is removed and on battery below 20 %; “Allow…” asks for the administrator password once (macOS's dialog) and installs `/etc/sudoers.d/claudepult`, checked by `visudo`, allowing only those two commands; “Remove…” removes it. Sleep turned off by another app is left alone. **“Quick Commands”**: a library of buttons — a script in the background (zsh in the home folder, the last output line as a notification), a script in Terminal, a Shortcuts shortcut, or opening a link / file / folder / app; optional “Ask before running”; edited in “Modules”. Each command may have a global keyboard shortcut (“Record” in its editor, ✕ clears; needs ⌘, ⌃ or ⌥, or a lone F1–F20): a Carbon hot key that works in any app while the module is installed and on, whatever the profile, and runs the command like its button — with “Ask before running” as an alert first; the panel shows it on the button. AI Hub Bar's own keys (the search key, the island's ⌃⌥Y / ⌃⌥N when on) win, and of two commands with the same keys the one higher in the library gets them; the editor says so under the shortcut, warns about macOS's own keys and ⌘-only keys, and about keys macOS refused. The library (and so the shortcuts) isn't part of `.claudepult` files. **“Quick Toggles”**: dark mode and desktop icons (showing their state), lock and turn off the display, eject disks, empty the Trash (after a confirmation), and “Notch island” — shows or hides the island, only while that module is installed; dark mode and the Trash ask for the Automation permission once. **“Clipboard History”**: the last copies (text and files; 20 / 50 / 100 / 200), search, pins, a click copies an entry back; copies marked as secret (`org.nspasteboard.ConcealedType` and similar) and anything copied in password managers or Keychain Access (list in “Modules”) are never recorded; kept in memory unless “Keep after restart” is on (`clipboard.json`, owner-only). **“Notes”**: Markdown files in one folder (`~/Documents/ClaudePult Notes` by default, changed in “Modules”), one tab each, saved a second after typing, deleted to the Trash, “Open in Editor”. **“Keyboard Layout”** (docs/specs/SPEC-layout.md): a word typed in the wrong layout (“ghbdtn”) is retyped in the right one once a space, Enter or Tab finishes it, and the layout switches; checked with the system spell checker in the layout's language (Russian, English, Ukrainian, German, French, Portuguese, Spanish); double Shift converts the last word or takes a fix back and learns the word (⌘Z right after a fix learns it too), ⌥⇧ converts the selection through the clipboard and puts the clipboard back; the layout's language in the menu bar blinks when it switches; not in terminals (switch) and never in password fields; needs Accessibility; nothing typed is stored. Template **“Mac Utilities”**: a profile without projects with these four modules. Settings → “Modules” is the catalog: what each module does, which profiles show it and its settings that don't depend on a profile (limits thresholds and sign-in renewal, calendar reminders). Settings → General → “Export Settings…” saves everything to a `*.claudepult` file, format version 2 (profiles with modules and menu bars; no keys or tokens; home paths as `~`); version 1 files still import. Double-clicking such a file in Finder imports it (“Replace all settings” or “Add profiles”). Oleh's settings: `docs/modes/oleh-developer.claudepult`. CLI: `AIHubBar --modes` lists profiles with their modules.

## Install

People get a `.dmg` from GitHub Releases, signed with the self-signed “ClaudePult Release” certificate and updated through Sparkle. Releasing it is covered in [docs/RELEASE.md](RELEASE.md) (`scripts/release.sh <version> [--publish]`). The code is under the MIT license ([LICENSE](../LICENSE)). From source:

Requirements: macOS 14+ (developed on macOS 27, Apple Silicon), Xcode with Swift 6 (developed with 27.1), `brew install xcodegen`.

```bash
scripts/build-and-install.sh
```

Generates `AIHubBar.xcodeproj` from `project.yml`, builds Release, installs `~/Applications/AI Hub Bar.app` and relaunches it. `--test` runs the unit tests first, `--no-launch` only installs. Signed ad-hoc; no Apple Developer account needed.

First steps after installing:

1. “Settings…” → “AI Services” → “Claude Code” → “Install hooks” (adds AI Hub Bar's hook to `~/.claude/settings.json`, backup saved next to it).
2. Optionally “Start at login”.
3. The first “Terminal” launch makes macOS ask to let AI Hub Bar control Terminal — allow it; notifications — allow them.
4. For the limits, macOS may ask whether `security` may read “Claude Code-credentials” — “Always Allow”.
5. Notifications must be allowed (System Settings → Notifications → AI Hub Bar); the panel warns while they are off, Settings → General → “Check” sends a test one.

Notifications are clickable: “Claude is waiting for an answer” → the session's Terminal tab; a finished background run → its PR (“Open PR”) or “Log”; a report → `latest.html`; cleanup → its output.

## Settings

“Settings…” (⌘,), one tab per area:

- **General** — start at login, a pointer to the “Telegram” module (the bot moved there), projects folder, `_daily-report` folder, feedback (“Suggest an Idea…” / “Report a Problem…” open the repository's issue forms, `.github/ISSUE_TEMPLATE`, with `version` and `macos` filled through the link's query; also at the bottom of “Help”), “Offer to send a report after a crash”, version, app log.
- **Appearance** — theme (system / light / dark, also for AI Hub Bar's windows), text size (small / normal / large / extra large; the panel widens with it), panel width, row density, opening animation, which blocks to show (Limits, Sessions, Projects, Commands), “Reset appearance”.
- **Menu Bar** — the menu bar builder (SPEC-modes §7): presets “Minimum” / “Limits” / “Everything” / “Custom”; elements in order, each on/off with its options (icon symbol or the mode's icon; session / week / model week as number, ring or bar, shown always or from N %; reset countdown “2:14” or “2 h 14 min”; forecast; waiting, running sessions, background runs, queued launches — only when > 0; free disk below N GB; current mode as icon or name); separator, small text, colour by level or mono; live preview with “Now” / “Everything example” and a warning when the item gets wider than 180 pt; under the preview the switched-on elements as chips in menu bar order — drag one onto another to move it there (the ˄ ˅ buttons in the list still work). CLI: `AIHubBar --menubar-preview <file.png> [minimum|limits|everything]` draws the item (dark and light) with sample data.
- **Modules** — the module catalog: description, which profiles show it, “Subscription limits” (thresholds, Telegram, “Renew the Claude Code sign-in automatically”) and “Reminders” of the calendar. Each AI service's page (Settings → AI Services → …) has “Limit notifications”: the common thresholds, its own, or none (`serviceThresholds`). The notch island (Settings → Modules → “Notch island”) has “Hide the island” (also a laptop icon in the panel header, and “Island” in Quick Toggles), “Summary — limits and sessions” (menu bar and island / island only — the menu bar keeps its icon and the projects' red dot / menu bar only — no ears), “Where to show” (screen with the notch / main screen / all screens — then one island per screen: the notch where there is one, the pill on the others if the pill is on; the same banners on each, the card opens on the one hovered) and “Pill on screens without a notch” (a black island centred under the menu bar, for events and the card only; on by default on a Mac without a notch); `AIHubBar --app-command test-island` shows a trial banner. Over a full-screen app the island stays, without ears, for requests and waits only. “⌃⌥Y / ⌃⌥N hot keys for requests” (off by default) allow or deny the request on the island once it has been shown for 0.6 s. ## Background mode

`claude -p "<prompt>" --session-id <run id> --output-format stream-json --verbose --permission-mode dontAsk --permission-prompts none --settings '<rules>'` in the project folder or a new worktree. Anything not allowed is denied without asking:

- allowed: reading files, editing/writing inside the working folder, project checks and builds (npm, pnpm, npx, yarn, bun, node, tsc, mvn, gradle, xcodebuild, xcodegen, xcrun, swift, expo, pytest, make, `scripts/*`), `git status/diff/log/show/branch/add/commit/mv/rm/checkout -b/switch/fetch`, `git push origin <branch>` / `-u origin <branch>`, `gh pr create/view/list/checks/status`;
- denied: push to main/master or HEAD, bare `git push`, force/delete/mirror pushes, `git reset --hard`, `git clean`, deleting branches, `gh pr merge`, `gh api`, `sudo`, `rm`, reading `.env`, keys, `~/.ssh`, `_daily-report/config.json`, printing the environment.

Full rule set: `AIHubBar --background-settings`. Log: `~/Library/Application Support/ClaudePult/runs/<id>.log`, shown readably by “Log”. Time limit from Settings, then SIGTERM. On finish: a notification and, if enabled and `_daily-report/config.json` has the bot, a Telegram message “✅/❌ <Project>: <start of the task> — <result>” with the PR link. A run keeps going if AI Hub Bar quits. Runs older than 30 days are deleted. Note: Bash rules are pattern matching, not a sandbox — see DECISIONS.md.

## Session hooks

The hook (`~/Library/Application Support/ClaudePult/hooks/claudepult-hook.py`) listens to `SessionStart`, `UserPromptSubmit`, `PermissionRequest`, `Notification`, `PostToolUse`, `Stop`, `StopFailure`, `SessionEnd` and writes one file per session to `~/Library/Application Support/ClaudePult/sessions/<session_id>.json` (state, cwd, project, first/last prompt up to 200 characters, Claude's pid and tty). It prints nothing and always exits 0, so it never changes what Claude does. “Remove hooks” removes only AI Hub Bar's entries. Session files older than 7 days are deleted.

## Command line

The app binary runs headless commands instead of the UI: `~/Applications/AI\\ Hub\\ Bar.app/Contents/MacOS/AIHubBar <command>`.

| Command | Effect |
|---|---|
| `--login-item status\|on\|off` | start at login |
| `--claude next\|finish <project>` · `--claude task <project> <text>` | Claude command in a new Terminal window (worktree if busy); `finish` exits 3 if the folder is busy |
| `--claude … --background` | as a background run; the running app reports the result |
| `--claude … --print` · `--claude-path <path>` | print the command line · use another binary (e.g. `/bin/echo`) |
| `--background-settings` | permission rules of background runs |
| `--command report\|summary\|cleanup-check\|cleanup` | run a common command here and print its result |
| `--app-command <command>\|help\|cleanup-output\|settings\|quick-prompt` | ask the running app to run a command or open a window (`quick-prompt`: the quick prompt window) |
| `--hooks status\|install\|uninstall` | session hooks |
| `--modes` · `--export-settings <file>` | list modes (* = current) · export all settings (import: open the file) |
| `--notifications-status` · `--app-command test-notification` | notification permission · send a test notification |
| `--readiness [file.png]` | what this Mac still needs (AI service, hooks, notifications, start at login); exit 1 while something is left |
| `--usage` · `--usage-raw` · `--token-usage` | subscription limits (raw response; the token is never printed) · per-project breakdown |
| `--sessions` · `--show-session <id>` | list sessions · bring a session's Terminal tab forward |

## Development

```bash
xcodegen generate
xcodebuild test -project AIHubBar.xcodeproj -scheme AIHubBar -destination 'platform=macOS,arch=arm64'
```

`AIHubBar.xcodeproj` and `AIHubBar/Info.plist` are generated from `project.yml` and not committed. The app icon is generated by `swift scripts/make-app-icon.swift`.

Layout: `AIHubBar/App` (entry point, command line), `Models` (report, sessions, runs, commands, formatting), `Services` (processes, stores, hooks, launcher, Telegram, settings, log), `Views` (panel, rows, sessions, commands, windows, settings, help), `Resources` (icon), `AIHubBarTests` (Swift Testing).

Logs: `~/Library/Logs/ClaudePult/ClaudePult.log` (rotated at 1 MB). No tokens or file contents are logged.

Crash reports: 3 s after launch the app looks in `~/Library/Logs/DiagnosticReports` for its own `AIHubBar-*.ips` / `ClaudePult-*.ips` written since the last check (`crashReportsCheckedAt`; the first check looks one day back; reports of the unit tests, which run inside the app, are skipped). For the newest one it asks “Report on GitHub…”: the bug form opens with the title `Crash: <exception> in <first frame of the app>`, the crashed thread's top 8 frames, the version from the report and the last 25 log lines (home folder replaced by `~`, account name by `USER`); a copy of the full report goes to the log folder as `.txt` and is shown in Finder. “Don't offer again” sets `askAfterCrash` to false; Settings → General switches it back. Code: `AIHubBar/Services/Feedback.swift`.

Panel snapshots for checks (the app's windows are hidden from screen-capture automation): `defaults write com.demishev.claudepult DebugPanelSnapshot -bool YES` saves `panel.png`, `help.png`, `cleanup.png` to the log folder whenever those windows show; `defaults write com.demishev.claudepult DebugPanelExpand <project>` expands a project. Layout and text are reliable, some colours are not. Turn off with `defaults delete com.demishev.claudepult DebugPanelSnapshot`.
